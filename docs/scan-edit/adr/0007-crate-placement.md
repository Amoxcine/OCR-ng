# ADR 0007 — Crate placement and dependencies

Status: accepted (S0). Decision D7 of the brief.

- `crates/scanedit` is `pdfcraft-scanedit`, layer **L4**, registered in `xtask/src/layers.rs`
  with one new same-layer edge, `scanedit → edit` (like `redact → edit`). It uses `page_images`,
  `text_lines`, `replace_line` and `stamp`.
- Other dependencies: `cos`, `content`, `model`, `fonts` (L0–L2) and `render` (L3). `render` is
  used only by the fixture generator (`synth`), which tests in the engine and automation also use.
  It is already in every build, compiles for wasm, and keeps fixtures generated by the
  repository's own renderer instead of committed files.
- No dependency on `pdfcraft-ocr` ([ADR 0004](0004-labels-from-the-text-layer.md)) and no ML
  runtime. All methods are classical. When a learned tier arrives (inpainting S8, glyph synthesis),
  it goes through `rten` as an optional asset (D8).
- Integration outside the crate stays thin, so the fork stays easy to sync: one `Edit` variant,
  one error variant, two `Doc` queries, one `Session` method (`engine/src/scan.rs`), three tools
  (`automation/src/scan.rs`) and their table entries.
